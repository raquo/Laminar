# Agent instructions

## Code comments
- Code comments must be concise, only added as needed, and should be framed to explain the what (e.g. as caption for a group of commands) and/or the why – e.g. why we're doing this, why it's safe, etc.
- Use your judgement to see what is unclear about the code from reading / skimming it, and only comment about that, don't comment obvious things.
- Comments should NOT be historical ("we did this, now we're doing that", "doing this because X is no longer Y", "this is <what user requested>, not <what user wanted to avoid>", etc.) – rather, they should only be concerned with commenting on the end state, ignoring how we came about to it.

## Specialized guides
- Before writing or modifying .md files, read [notes/Markdown.md](notes/Markdown.md) for style guide.
- Before writing or modifying tests, read [notes/Testing.md](notes/Testing.md) for this suite's conventions (EventTracker, event-sequence assertions, sectioning, etc.).
